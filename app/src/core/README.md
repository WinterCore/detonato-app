# core/

The app's rules as plain functions. No React, no storage: data in, answers
out, every file with a test beside it. Screens and `state/` call these;
these call nothing outside `core/`.

| File | Answers |
|---|---|
| `types.ts` | What the data looks like: a display design (`Glyph`), a task and its plans, a session finished, the snapshot of both |
| `tasks.ts` | Which plan does a task have on a day, which tasks are on today, and what does an edit or a delete make of a task? |
| `progress.ts` | How much of a day got done, how dark is its square, how long is the streak, how many minutes of focus? |
| `history.ts` | Over many days: the best streak, the perfect days, the focus, how each task has gone |
| `settings.ts` | What can be set, its defaults, and the settings read back from anything (`parseSettings`) |
| `timer.ts` | Where is the session — running, held, done — and what does each tap make it? How long is left? What does it log once it ends? |
| `notice.ts` | What does the end-of-session notification say? |
| `sounds.ts` | What does each end-of-session sound play, from which file, on which Android channel? |
| `backup.ts` | What's in a backup, and is this file one we can restore? |
| `segments/glyphs.ts` | Every design on Posy's sheet (`glyphs.json`, generated by `pnpm glyphs`) |
| `segments/digits.ts` | Which segments light to show this character? |
| `segments/families.ts` | The designs by family, their names, and what to know before picking one |
| `time/calendar.ts` | Which local day is it (`DayKey`), what's a day before or after, which weekday, how long to midnight? |

Logic that serves one screen lives with that screen instead, under
`screens/<feature>/lib/`.
